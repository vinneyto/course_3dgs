# Учебный растеризатор 3D Gaussian Splatting

Этот репозиторий содержит учебную реализацию рендеринга сцены 3D Gaussian
Splatting на PyTorch. Основной код находится в [`3dgs.ipynb`](3dgs.ipynb), а
вспомогательные операции — в [`util.py`](util.py).

Текущая версия проверена на Apple Silicon с backend `mps`. Она повторяет
математику CUDA-референса автора курса, но отличается в нескольких инженерных
местах: использует аналитическое разложение симметричной матрицы 2×2,
компактно строит список пересечений гауссианов с тайлами и сортирует тайлы без
большого составного целочисленного ключа.

## Алгоритм на верхнем уровне

Каждый 3D-гауссиан задаёт небольшой полупрозрачный эллипсоид в мировом
пространстве. Растеризатор:

1. проецирует центр гауссиана на экран;
2. проецирует его трёхмерную ковариацию в двумерную экранную ковариацию;
3. вычисляет экранный прямоугольник гауссиана;
4. находит все тайлы изображения, пересекающиеся с этим прямоугольником;
5. группирует пересечения по идентификатору тайла, сохраняя порядок по глубине;
6. внутри каждого тайла вычисляет вклад гауссианов в пиксели;
7. смешивает цвета от ближних гауссианов к дальним с помощью alpha compositing.

Изображение разбивается на тайлы размером `T × T`, по умолчанию `16 × 16`.
Для тайла с двумерными координатами `(tile_u, tile_v)` используется линейный
идентификатор:

```text
num_tiles_u = ceil(W / T)
flat_tile_id = tile_v * num_tiles_u + tile_u
```

Обратное преобразование:

```text
tile_u = flat_tile_id % num_tiles_u
tile_v = flat_tile_id // num_tiles_u
```

После сортировки по `flat_tile_id` все гауссианы одного тайла лежат в одном
непрерывном диапазоне массива. Благодаря этому основной цикл может идти только
по непустым тайлам и брать для каждого тайла уже готовый список гауссианов.

### Псевдокод

```text
activate opacity, scale, and quaternion
build world-space Gaussian covariances

project Gaussian centers into camera space and pixel coordinates
discard Gaussians outside the camera working area

for each Gaussian:
    project the 3×3 covariance into a 2×2 covariance
    stabilize the eigenvalues of the 2×2 covariance

sort Gaussians by depth: near → far

for each Gaussian:
    compute its screen-space AABB
    convert the AABB bounds into tile_u and tile_v ranges
    create only existing (gaussian_id, flat_tile_id) pairs

stably sort the pairs by flat_tile_id
store the [start, end) range for each non-empty tile

for each non-empty tile:
    build its pixel coordinates
    select Gaussians from the [start, end) range
    compute the quadratic form q for each Gaussian × pixel pair
    compute alpha
    compute accumulated transmittance T
    sum alpha * T * color

assemble the tiles into the final H × W × 3 image
```

## Обозначения размеров тензоров

В комментариях ноутбука используются следующие обозначения:

| Обозначение | Значение |
| --- | --- |
| `N0` | количество входных гауссианов |
| `Nf` | количество гауссианов после frustum-фильтрации |
| `Nk` | количество гауссианов после удаления `NaN` и `Inf` |
| `Ns` | количество гауссианов, AABB которых пересекает экран |
| `K` | общее количество пересечений «гауссиан × тайл» |
| `U` | количество непустых тайлов |
| `G` | количество гауссианов текущего тайла |
| `P` | количество пикселей текущего тайла, не больше `T * T` |

## 1. Параметры гауссиана и мировая ковариация

Для каждого гауссиана используются:

```text
position:    [N0, 3]
color:       [N0, 3]
opacity_raw: [N0] или [N0, 1]
scale_raw:   [N0, 3]
rot_raw:     [N0, 4]
```

Масштабы хранятся в логарифмической форме:

```python
scale = torch.exp(scale_raw).clamp_min(1e-6)
```

Кватернион нормализуется и преобразуется в матрицу вращения `R`. В данных
проекта компоненты `rot_raw` расположены в порядке `[x, y, z, w]`, который
ожидает `quat_to_mat`.

Матрица масштаба:

```text
S = diag(scale_x, scale_y, scale_z)
```

Мировая ковариация:

```text
Sigma_world = R * S * S * transpose(R)
```

В коде:

```python
S = torch.diag_embed(scale)
sigma = R @ S @ S @ R.transpose(1, 2)
```

`S * S` эквивалентно диагональной матрице квадратов масштабов.

> **Отличие от CUDA-референса.** Референс вызывает
> `build_sigma_from_params`, а текущая версия явно использует
> `build_covariance` из `util.py`. Математический результат тот же: нормализация
> вращения, активация масштаба через `exp` и построение `R S² Rᵀ`.

## 2. Проекция центров на экран

`project_points` сначала строит преобразование из мирового пространства в
пространство камеры. Входная матрица `c2w` описывает преобразование
camera-to-world, поэтому для перехода world-to-camera используются:

```text
R_wc = transpose(R_cw)
t_wc = -R_wc * t_cw
```

После преобразования центр гауссиана имеет координаты камеры `(x, y, z)`.
Пиксельные координаты вычисляются перспективной проекцией:

```text
u = fx * x / z + cx
v = fy * y / z + cy
```

Результат:

```text
uv: [N0, 2]
x, y, z: [N0]
```

## 3. Frustum-фильтрация

До дорогих матричных операций отбрасываются гауссианы:

- расположенные ближе `near` или дальше `far`;
- находящиеся далеко за границами изображения;
- не способные заметно повлиять на изображение с учётом `pix_guard`.

```python
frustum = (
    (u > -pix_guard)
    & (u < W + pix_guard)
    & (v > -pix_guard)
    & (v < H + pix_guard)
    & (z > near)
    & (z < far)
)
```

Opacity активируется сигмоидой:

```python
opacity = torch.sigmoid(opacity_raw[frustum]).squeeze(-1).clamp(0, 0.999)
```

> **Отличие от CUDA-референса.** В MPS-версии добавлен `squeeze(-1)`, поэтому
> одинаково обрабатываются opacity формы `[N]` и `[N, 1]`. Это отличие формы
> тензора, а не алгоритма рендеринга.

## 4. Проекция ковариации из 3D в 2D

Сначала мировая ковариация поворачивается в систему координат камеры:

```text
Sigma_camera = R_wc * Sigma_world * transpose(R_wc)
```

Перспективная проекция нелинейна, поэтому около центра каждого гауссиана она
линеаризуется матрицей Якоби `J`:

```text
J = [[fx/z,    0, -fx*x/z²],
     [   0, fy/z, -fy*y/z²]]
```

Экранная ковариация:

```text
Sigma_uv = J * Sigma_camera * transpose(J)
```

Форма тензора меняется так:

```text
[Nf, 3, 3] → [Nf, 2, 2]
```

После вычисления симметрия восстанавливается явно:

```python
sigma_uv = 0.5 * (sigma_uv + sigma_uv.transpose(1, 2))
```

Это убирает небольшую численную асимметрию, появившуюся из-за операций
`float32`.

> **Отличие от CUDA-референса.** В референсе двумерная матрица после умножения
> на `J` продолжает называться `sigma_camera`. Текущая версия использует имя
> `sigma_uv`, чтобы явно отличать `[N, 2, 2]` от трёхмерной ковариации камеры
> `[N, 3, 3]`. Математика не меняется.

## 5. Стабилизация экранной ковариации

Для определения размера эллипса и предотвращения вырожденных матриц выполняется
собственное разложение:

```text
Sigma_uv = V * diag(lambda) * transpose(V)
```

Собственные значения ограничиваются диапазоном:

```python
evals = torch.clamp(evals, min=1e-6, max=1e4)
```

Затем ковариация собирается обратно. Минимальная граница защищает от почти
нулевого эллипса и нестабильного обращения, максимальная ограничивает размер
экранного гауссиана и потребление памяти.

Матрицы, содержащие `NaN` или `Inf`, удаляются до дальнейшей обработки.

> **Отличие от CUDA-референса.** Автор использует `torch.linalg.eigh`, который
> работает на CUDA, но не реализован для используемого MPS backend. Текущая
> версия вызывает аналитическую функцию `eigh_2x2` из `util.py`. Она использует
> специальную формулу для симметричной матрицы 2×2, возвращает собственные
> значения по возрастанию и собственные векторы в столбцах. Это позволяет
> выполнить тот же шаг без переноса тензоров на CPU.

## 6. Глобальная сортировка по глубине

Alpha compositing зависит от порядка, поэтому перед построением тайлов все
оставшиеся гауссианы сортируются от ближних к дальним:

```python
z, order = torch.sort(z, descending=False)
```

Та же перестановка применяется к `uv`, `color`, `opacity`, `sigma_uv` и
`evals`. После этого индекс гауссиана в массивах одновременно является его
позицией в глобальном порядке глубины.

Эта инварианта используется дальше: стабильная сортировка по ID тайла может
сгруппировать гауссианы по тайлам, не разрушив их глубинный порядок.

## 7. Экранный AABB гауссиана

Наибольшее собственное значение `Sigma_uv` задаёт дисперсию вдоль большой оси
экранного эллипса:

```python
major_variance = evals[:, 1].clamp_min(1e-12).clamp_max(1e4)
radius = torch.ceil(3.0 * torch.sqrt(major_variance)).to(torch.int64)
```

Круг радиуса `3σ` гарантированно содержит эллипс, поэтому его удобно использовать
для консервативного экранного AABB:

```python
umin = torch.floor(u - radius).to(torch.int64)
umax = torch.floor(u + radius).to(torch.int64)
vmin = torch.floor(v - radius).to(torch.int64)
vmax = torch.floor(v + radius).to(torch.int64)
```

AABB, не пересекающие изображение, удаляются. Остальные границы ограничиваются
размерами изображения.

## 8. Переход от пиксельного AABB к диапазону тайлов

Пиксельные границы переводятся в координаты тайлов целочисленным делением:

```python
umin_tile = umin // T
umax_tile = umax // T
vmin_tile = vmin // T
vmax_tile = vmax // T
```

Количество затронутых тайлов по каждой оси:

```python
n_u = umax_tile - umin_tile + 1
n_v = vmax_tile - vmin_tile + 1
```

Число пересечений одного гауссиана:

```text
num_tiles_per_gaussian = n_u * n_v
```

А общее число реальных пересечений:

```text
K = sum(num_tiles_per_gaussian)
```

## 9. Компактное построение пересечений «гауссиан × тайл»

Для каждого гауссиана его ID повторяется столько раз, сколько тайлов он
пересекает:

```python
gaussian_ids = torch.repeat_interleave(
    torch.arange(num_gaussians, device=device, dtype=torch.int64),
    num_tiles_per_gaussian,
    output_size=num_tile_intersections,
)
```

Пример:

```text
num_tiles_per_gaussian = [2, 1, 3]
gaussian_ids            = [0, 0, 1, 2, 2, 2]
```

`cumsum` вычисляет начало сегмента каждого гауссиана в плоском массиве:

```text
counts  = [2, 1, 3]
cumsum  = [2, 3, 6]
starts  = [0, 2, 3]
```

Локальный ID пересечения внутри прямоугольника тайлов:

```python
local_tile_ids = (
    torch.arange(K, device=device, dtype=torch.int64)
    - starts_per_gaussian[gaussian_ids]
)
```

Внутри прямоугольника координата `v` изменяется быстрее:

```python
local_tile_u = local_tile_ids // n_v[gaussian_ids]
local_tile_v = local_tile_ids % n_v[gaussian_ids]
```

Глобальные координаты и линейный ID тайла:

```python
flat_tile_u = umin_tile[gaussian_ids] + local_tile_u
flat_tile_v = vmin_tile[gaussian_ids] + local_tile_v

num_tiles_u = (W + T - 1) // T
flat_tile_id = flat_tile_v * num_tiles_u + flat_tile_u
```

Таким образом создаются тензоры длины ровно `K`, без заполнителей для
несуществующих пересечений.

> **Отличие от CUDA-референса.** Референс сначала создаёт плотные тензоры
> `[Ns, max_u, max_v]`, а затем удаляет лишние элементы маской. Их размер
> пропорционален `Ns * max_u * max_v`, даже если большинство гауссианов
> пересекает мало тайлов. Текущая версия сразу строит только `K` реальных
> пересечений. Это существенно снижает пиковое потребление unified memory на
> Apple Silicon.

## 10. Стабильная сортировка по идентификатору тайла

Полученные пары нужно сгруппировать по `flat_tile_id`:

```python
tile_ids_1d, perm = torch.sort(
    flat_tile_id,
    stable=True,
)
gaussian_ids = gaussian_ids[perm]
```

Здесь критически важен параметр `stable=True`. До этого шага гауссианы уже
расположены от ближних к дальним. Стабильная сортировка меняет порядок групп
тайлов, но сохраняет исходный порядок элементов с одинаковым `flat_tile_id`.
Следовательно, внутри каждого тайла гауссианы остаются отсортированными по
глубине.

После сортировки одинаковые ID идут подряд:

```text
tile_ids_1d = [0, 0, 0, 1, 1, 4, 4, 4, ...]
```

`torch.unique_consecutive` возвращает ID непустых тайлов и размеры групп.
Префиксная сумма размеров формирует диапазоны:

```text
counts = [3, 2, 3]
start  = [0, 3, 5]
end    = [3, 5, 8]
```

Для тайла `i` его гауссианы находятся в срезе:

```python
tile_gaussian_ids = gaussian_ids[start[i]:end[i]]
```

> **Отличие от CUDA-референса.** Референс кодирует пару
> `(flat_tile_id, depth_order)` в одном большом ключе:
>
> ```python
> M = num_gaussians + 1
> comp = flat_tile_id * M + depth_order
> comp_sorted, perm = torch.sort(comp)
> tile_ids_1d = comp_sorted // M
> ```
>
> На CUDA эта схема работает корректно. На MPS сортировка больших составных
> `int64`-ключей приводила к нарушению группировки или порядка элементов, что
> проявлялось границами тайлов разной интенсивности. Стабильная сортировка
> непосредственно по `flat_tile_id` использует уже существующий глубинный
> порядок, не создаёт большие ключи и устраняет артефакт сетки.

## 11. Обращение экранной ковариации

Для вычисления плотности нужна обратная матрица:

```text
A = inverse(Sigma_uv)
```

`inv2x2` использует явную формулу обращения матрицы 2×2. Определитель
ограничивается снизу, а диагональные элементы результата дополнительно
ограничиваются параметром `min_conis`.

Результат:

```text
inverse_covariance: [Ns, 2, 2]
```

## 12. Обход непустых тайлов

Цикл выполняется только для ID, присутствующих в `unique_tile_ids`.
Координаты тайла восстанавливаются из линейного ID:

```python
txi = tile_id % num_tiles_u
tyi = tile_id // num_tiles_u
```

Пиксельные границы:

```python
x0 = txi * T
y0 = tyi * T
x1 = min((txi + 1) * T, W)
y1 = min((tyi + 1) * T, H)
```

`min` необходим для крайних тайлов, если ширина или высота изображения не
делится на `T`.

Координаты всех пикселей тайла строятся через `torch.meshgrid` и превращаются
в плоские тензоры длины `P`:

```text
px_u: [P]
px_v: [P]
```

## 13. Значение двумерного гауссиана в пикселях

Для текущего тайла одновременно рассматриваются `G` гауссианов и `P` пикселей.
Разности координат используют broadcasting:

```python
du = px_u.unsqueeze(0) - gaussian_i_u.unsqueeze(-1)  # [G, P]
dv = px_v.unsqueeze(0) - gaussian_i_v.unsqueeze(-1)  # [G, P]
```

Для обратной ковариации

```text
A = [[A11, A12],
     [A12, A22]]
```

квадратичная форма равна:

```text
q = A11*du² + 2*A12*du*dv + A22*dv²
```

Значение гауссиана:

```text
g = exp(-0.5*q)
```

Далёкие хвосты обрезаются:

```python
inside = q <= chi_square_clip
g = torch.where(inside, g, torch.zeros_like(g))
```

При `chi_square_clip=9.21` остаётся ограниченная эллиптическая область вокруг
центра гауссиана.

## 14. Alpha compositing

Пиксельная alpha одного гауссиана:

```python
alpha_i = (
    gaussian_i_opacity.unsqueeze(-1) * g
).clamp_max(alpha_max)
```

Очень маленькие значения отбрасываются:

```python
alpha_i = torch.where(
    alpha_i >= alpha_cutoff,
    alpha_i,
    torch.zeros_like(alpha_i),
)
```

Для каждого пикселя прозрачность перед гауссианом `i` равна произведению
прозрачностей всех предыдущих гауссианов:

```text
T_i = product для j < i от (1 - alpha_j)
```

Векторизованная реализация сначала вычисляет включительный `cumprod`, а затем
сдвигает его на одну строку:

```python
T_i = torch.cumprod(1 - alpha_i, dim=0)
T_i = torch.concatenate([
    torch.ones((1, alpha_i.shape[-1]), device=device, dtype=dt),
    T_i[:-1],
], dim=0)
```

Вес гауссиана:

```text
w_i = alpha_i * T_i
```

Итоговый цвет пикселя:

```text
color_pixel = sum_i(w_i * color_i)
```

Так как `T_i` зависит от всех предыдущих alpha, перестановка гауссианов меняет
цвет. Поэтому сохранение порядка глубины внутри каждого тайла принципиально
важно.

## 15. Сборка изображения

Цвета пикселей тайла записываются в плоский буфер по глобальным индексам:

```python
pixel_idx_1d = (px_v * W + px_u).to(torch.int64)
final_image[pixel_idx_1d] = tile_color
```

После обработки тайлов буфер преобразуется в изображение и ограничивается
диапазоном `[0, 1]`:

```python
return final_image.reshape((H, W, 3)).clamp(0, 1)
```

| Устройство | `.cuda()` и CUDA | `torch.device("mps")` и `.to(device)` |
| Собственное разложение 2×2 | `torch.linalg.eigh` | аналитический `eigh_2x2` |
| Мировая ковариация | `build_sigma_from_params` | `build_covariance`, явно вычисляющий `R S² Rᵀ` |
| Имя экранной ковариации | `sigma_camera` после проекции | более точное `sigma_uv` |
| Пересечения с тайлами | плотные `[Ns, max_u, max_v]` и маска | компактные тензоры длины `K` |
| Сортировка пересечений | составной ключ `tile_id * M + depth_order` | стабильная сортировка по `flat_tile_id` |
| Порядок внутри тайла | закодирован в составном ключе | сохранён стабильностью сортировки |
| Потребление памяти | зависит от максимального AABB среди всех гауссианов | пропорционально числу реальных пересечений `K` |
| Форма opacity | предполагается совместимая с дальнейшими операциями | явно приводится к `[N]` через `squeeze(-1)` |
| Комментарии | краткие | формы основных тензоров указаны непосредственно в коде |

При попиксельном сравнении сохранённых PNG размером `1559 × 1039` после
исправления сортировки отличались только 33 пикселя из 1 619 801. Максимальное
отклонение составляло 1 уровень одного RGB-канала из 255, а PSNR — примерно
99.43 dB. На уровне итогового восьмибитного изображения результаты практически
идентичны; оставшаяся разница соответствует обычным различиям вычислений
`float32` и округления при переводе в `uint8`.

## Вычислительная сложность и ограничения

Основные объёмы данных:

- параметры и спроецированные ковариации: `O(N)`;
- список пересечений гауссианов с тайлами: `O(K)`;
- временные тензоры текущего тайла: `O(G * P)`;
- итоговое изображение: `O(H * W)`.

Текущая реализация остаётся учебной:

- тайлы обрабатываются циклом Python;
- для каждого тайла создаются временные тензоры `[G, P]`;
- нет раннего завершения compositing после достижения почти полной
  непрозрачности;
- нет специализированного GPU-ядра для binning, сортировки и растеризации.

Несмотря на это, реализация показывает полный путь данных 3DGS: от мировых
эллипсоидов и проекции ковариации до тайлов, квадратичной формы и
front-to-back alpha compositing.
